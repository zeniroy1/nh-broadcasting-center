# 무신사 검색 및 파싱 기반 제품 추천 프로그램 기술 구현 계획서

## 1. 목적 정의

이 프로그램의 목적은 무신사에서 사용자가 원하는 제품에 더 빠르게 도달하도록 돕는 것이다. 단순히 상품 목록을 많이 보여주는 것이 아니라, 사용자의 자연어 요청을 구매 조건으로 분해하고, 공개적으로 확인 가능한 지표를 수집한 뒤, 내부 데이터에 가까운 대체 지표를 만들어 상품 후보를 비교한다.

예시 요청:

```text
검은색 무지 반팔티를 사고 싶다.
가격은 2~3만원대.
40대 남성이 무난하게 입을 만한 제품이면 좋겠다.
브랜드는 2~3개 정도로 추려서 비교하고 싶다.
```

핵심 목표:

```text
사용자 요청
→ 검색 조건 변환
→ 공개 지표 수집
→ 대체 지표 계산
→ 후보 상품 비교
→ 구매 판단 로드맵 제공
```

## 2. 기본 원칙

무신사 내부 데이터는 직접 알 수 없으므로 단정하지 않는다.

예를 들어 다음 정보는 내부 지표에 가깝기 때문에 직접 확인할 수 없거나 제한된다.

```text
정확한 구매자 수
40대 남성 구매자 수
연령대별 구매 비율
성별별 전환율
광고 노출 가중치
개인화 추천 점수
반품률
재구매율
```

따라서 프로그램은 공개 지표를 기반으로 대체 지표를 만든다.

예시:

```text
40대 남성 구매자 수
→ 남성/40대 랭킹 노출 여부
→ 남성 랭킹 순위
→ 리뷰 수
→ 평점
→ 판매 라벨
→ 베이직/무지 디자인 적합도
```

## 3. 10단계 기술 구현 로드맵

### 1단계. 사용자 요청 해석 모듈 설계

사용자의 자연어 요청을 구조화된 검색 조건으로 변환한다.

입력 예시:

```text
검은색 반팔 무지티, 2~3만원대, 40대 남성이 많이 산 제품
```

변환 결과 예시:

```text
상품군: 반팔 티셔츠
색상: 블랙
스타일: 무지, 베이직, 로고 적음
가격대: 20,000~39,999원
성별: 남성
연령대 힌트: 40대
우선순위: 무난함, 신뢰도, 구매 근거
```

산출물:

```text
검색 조건 스키마
사용자 요청 파싱 규칙
필수 조건/선호 조건/제외 조건 구분 기준
```

### 2단계. 무신사 공개 데이터 구조 조사

무신사에서 공개적으로 접근 가능한 데이터 범위를 정리한다.

조사 대상:

```text
검색 결과 페이지
랭킹 페이지
카테고리 페이지
상품 상세 페이지
리뷰/후기 영역
브랜드 페이지
```

확인할 데이터:

```text
상품 ID
상품명
브랜드
카테고리
가격
할인율
이미지
상품 URL
랭킹 순위
리뷰 수
평점
판매 라벨
배송 정보
품절 여부
옵션/사이즈 정보
```

산출물:

```text
페이지별 수집 가능 데이터 목록
API/HTML/초기 JSON 데이터 위치 정리
수집 가능/불가능 데이터 구분표
```

### 3단계. 공개 지표와 대체 지표 매핑 설계

내부 지표를 직접 수집하지 않고 공개 지표로 대체하는 기준을 만든다.

매핑 예시:

| 내부적으로 알고 싶은 지표 | 공개 지표 기반 대체 지표 |
|---|---|
| 실제 누적 구매자 수 | 판매 라벨, 리뷰 수, 랭킹 노출 |
| 40대 남성 구매자 수 | 남성/40대 랭킹 순위, 남성 랭킹 순위 |
| 성별별 구매 반응 | 남성/여성 필터별 랭킹 순위 비교 |
| 구매 전환율 | 현재 구매 중, 현재 보는 중, 리뷰 수 |
| 반품률 | 낮은 평점 리뷰, 사이즈 불만 키워드 |
| 재구매율 | 재구매 관련 리뷰 키워드 |
| 광고 영향 | AD/스폰서/기획전 표시 여부 |
| 검색 노출 점수 | 검색 결과 순위, 정렬 기준별 위치 |

산출물:

```text
대체 지표 정의서
지표별 신뢰도 등급
추정 지표 표기 원칙
```

### 4단계. 검색 후보 생성 로직 설계

사용자의 요청을 기반으로 여러 검색어 후보를 만든다.

예시:

```text
검은색 무지 반팔티
블랙 무지 반팔
남성 기본 반팔티
베이직 반팔 티셔츠
무지 크루넥 티셔츠
```

검색어를 하나만 쓰면 결과가 좁거나 왜곡될 수 있으므로, 여러 검색어에서 후보를 모은 뒤 중복을 제거한다.

산출물:

```text
검색어 생성 규칙
동의어 사전
카테고리 매핑 규칙
제외 키워드 규칙
```

### 5단계. 상품 목록 수집 범위 설계

검색 결과, 랭킹 결과, 카테고리 결과에서 후보 상품 목록을 수집한다.

수집 기준:

```text
검색어별 상위 N개 상품
남성 랭킹 상위 N개 상품
40대 필터 랭킹 상위 N개 상품
카테고리별 상위 N개 상품
가격대 조건에 맞는 상품
```

주의사항:

```text
광고 상품과 일반 상품 구분
중복 상품 제거
품절 상품 제외 여부 결정
같은 상품의 색상/옵션 처리 기준 결정
```

산출물:

```text
후보 상품 수집 정책
중복 제거 기준
검색/랭킹/카테고리별 수집 우선순위
```

### 6단계. 상품 상세 데이터 수집 설계

후보 상품별 상세 페이지에서 구매 판단에 필요한 데이터를 추가 수집한다.

상세 수집 항목:

```text

브랜드 정보
정상가
판매가
할인율
상품 이미지
카테고리
성별
시즌
배송 예정일
플러스배송 여부
리뷰 수
평점
상품 설명
소재/핏 설명
사이즈 옵션
품절 여부
랭킹 기록
```

산출물:

```text
상품 상세 데이터 스키마
상품별 원본 지표 저장 구조
상세 페이지 파싱 규칙
```

### 7단계. 리뷰 기반 보조 지표 설계

리뷰는 사용자의 실제 착용 경험을 반영하므로, 상품 점수 계산에 보조 지표로 사용한다.

분석할 리뷰 요소:

```text
사이즈가 크다/작다
비침이 있다/없다
목 늘어남
세탁 후 변형
원단 두께
핏 만족도
재구매 언급
색상별 구매 언급
40대/아빠/남편/직장/출근 등 타겟 키워드
```

주의:

```text
리뷰 키워드는 실제 통계가 아니라 사용자 경험의 단서로만 사용한다.
```

산출물:

```text
리뷰 키워드 사전
긍정/부정 신호 분류 기준
리뷰 기반 리스크 요약 방식
```

### 8단계. 점수화 모델 설계

수집한 공개 지표를 바탕으로 상품별 점수를 계산한다.

권장 점수 항목:

```text
목적 적합도 점수
인기 근거 점수
신뢰도 점수
남성 적합도 점수
40대 적합도 추정 점수
가격 적합도 점수
배송 편의 점수
리뷰 리스크 점수
광고 영향 보정 점수
```

예시 가중치:

```text
목적 적합도: 30%
신뢰도: 20%
남성/연령대 적합도 추정: 15%
가격 적합도: 15%
인기 근거: 10%
배송/품절: 5%
리뷰 리스크: 5%
```

산출물:

```text
점수 계산 기준표
가중치 설정표
추정 점수 설명 문구
```

### 9단계. 후보 상품 비교 및 추천 출력 설계

최종 결과는 단순 순위가 아니라 사용자가 바로 판단할 수 있는 비교표로 제공한다.

출력 예시:

```text

- 브랜드:
- 상품명:
- 가격:
- 추천 이유:
- 공개 근거:
- 주의점:
- 적합도:

추천 후보 2
- 브랜드:
- 상품명:
- 가격:
- 추천 이유:
- 공개 근거:
- 주의점:
- 적합도:
```

비교 기준:

```text
가격
브랜드
리뷰 수
평점
판매 라벨
남성 랭킹 노출
40대 필터 랭킹 노출
배송
품절 여부
리뷰 리스크
```

산출물:

```text
상품 비교표 포맷
추천 사유 템플릿
주의점 요약 템플릿
구매 판단 로드맵 출력 형식
```

### 10단계. 사용자 피드백 반영 구조 설계

추천 결과를 사용자가 다시 조정할 수 있어야 한다.

피드백 예시:

```text
로고 없는 제품만 보여줘
더 저렴한 제품으로 다시 골라줘
배송 빠른 제품만 남겨줘
리뷰 많은 순으로 다시 정렬해줘
너무 젊은 느낌은 제외해줘
브랜드를 무신사 스탠다드 제외하고 보여줘
```

피드백 반영 방식:

```text
조건 강화
조건 완화
제외 키워드 추가
브랜드 제외
가격대 재설정
점수 가중치 변경
후보 재정렬
```

산출물:

```text
피드백 명령어 분류표
재검색/재점수화 규칙
추천 결과 업데이트 흐름
```

## 4. 최종 시스템 흐름

```text
1. 사용자가 원하는 제품을 자연어로 입력한다.
2. 프로그램이 조건을 구조화한다.
3. 검색어 후보를 만든다.
4. 무신사 검색/랭킹/카테고리 자료를 수집한다.
5. 상품 상세 페이지를 수집한다.
6. 공개 지표를 정리한다.
7. 내부 지표를 대체할 추정 지표를 계산한다.
8. 상품별 종합 점수를 만든다.
9. 브랜드/상품 중복을 정리한다.
10. 최종 후보와 구매 판단 로드맵을 제공한다.
```

## 6. 표현 원칙

프로그램은 확인 가능한 사실과 추정 결과를 반드시 구분해야 한다.

나쁜 표현:

```text
40대 남성이 가장 많이 산 상품입니다.
```

좋은 표현:

```text
남성/40대 조건의 랭킹 노출, 리뷰 수, 평점, 판매 라벨을 기준으로 40대 남성에게 적합할 가능성이 높은 상품입니다.
```

나쁜 표현:

```text
반품률이 낮은 상품입니다.
```

좋은 표현:

```text
낮은 평점 리뷰에서 사이즈/품질 불만 키워드가 적어 반품 리스크가 낮을 가능성이 있습니다.
```

## 7. 기대 효과

현재 무신사에서 사용자가 직접 제품을 찾으면 다음 과정을 거쳐야 한다.

```text
검색어 입력
필터 적용
랭킹 확인
상품 상세 확인
리뷰 확인
브랜드 비교
가격 비교
배송 확인
후보 재정리
```

이 과정은 일반 사용자 기준 30~50분 이상 걸릴 수 있다.

이 프로그램은 해당 과정을 다음처럼 줄이는 것을 목표로 한다.

```text
사용자 요청 입력
→ 후보 상품 3~5개 비교
→ 추천 이유와 주의점 확인
→ 구매 페이지 이동
```

목표 시간:

```text
기존 탐색: 30~50분
프로그램 사용 후: 3~5분
```

## 8. 구현 전 확인해야 할 사항

코드 작성 전에 다음 사항을 먼저 확정해야 한다.

```text
1. 첫 MVP 대상 카테고리
2. 사용할 공개 지표 범위
3. 리뷰까지 수집할지 여부
4. 랭킹 페이지 중심으로 갈지 검색 페이지 중심으로 갈지
5. 사용자 입력을 자연어로 받을지 폼으로 받을지
6. 최종 결과를 표로 보여줄지 리포트로 보여줄지
7. 광고 상품을 제외할지 별도 표시할지
8. 점수 가중치를 고정할지 사용자별로 조정할지
9. 법적/약관/요청 빈도 제한 정책
10. 저장 데이터의 갱신 주기
```

## 9. MVP 제안

첫 번째 MVP는 범위를 좁히는 것이 좋다.

추천 MVP:

```text
무신사 남성 반팔 티셔츠 추천 도우미
```

MVP 조건:

```text
카테고리: 반팔 티셔츠
색상: 블랙/화이트/그레이
```

## 10. 최종 정리

이 프로그램은 무신사 내부 데이터를 알아내는 도구가 아니라, 공개 자료를 구조화해서 사용자의 구매 판단을 돕는 도구다.

핵심 가치는 다음 세 가지다.

```text
1. 복잡한 검색 과정을 줄인다.
2. 공개 지표 기반으로 추천 이유를 설명한다.
3. 확인 불가능한 내부 데이터는 대체 지표로만 조심스럽게 추정한다.
```

따라서 기술 구현의 중심은 파싱 자체보다 다음에 있다.

```text
사용자 의도 해석
공개 지표 수집
대체 지표 설계
점수화
설명 가능한 추천 결과
```
