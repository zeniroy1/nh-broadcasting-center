## 5. 문제 원인 판단

### 1. GPS 정확도 불안정

타사용자 로그에서는 정확도 `80m~125m` 수준의 위치가 자주 등장했습니다.

이 상태에서는 앱이 지오펜스 안/밖을 명확히 판단하지 못하고 다음 상태가 반복됩니다.

```text

경계 흔들림
EXIT 후 GPS 흔들림 무시
timeout후 lastKnown 사용
```

### 2. 위치요청 timeout 반복

로그에는 다음과 같은 실패 흐름이 반복되었습니다.

```text

TimeoutException after 0:00:25
위치 요청 timeout
timeout후 lastKnown 사용
```

이는 위치 요청이 즉시 끝나지 않고 15~25초씩 대기했다는 뜻입니다. 이 상태가 반복되면 같은 감시 횟수라도 배터리 소모가 크게 증가합니다.

### 3. Flutter 감시와 네이티브 보조 감시의 중복

Flutter 백그라운드 감시와 네이티브 보조 감시가 독립적으로 동작하면서 같은 시간대에 위치 확인을 각각 수행할 수 있습니다.

정상 환경에서는 큰 문제가 되지 않을 수 있지만, GPS가 불안정한 환경에서는 다음 문제가 발생합니다.

- Flutter 위치요청
- 네이티브 위치요청
- timeout 대기
- lastKnown fallback
- 짧은 주기로 재확인

이 조합이 배터리 소모의 핵심입니다.

사용자 본인은 S23+이고 타사용자는 S23 계열이므로 하드웨어 차이는 크지 않습니다. 이번 차이는 기기 성능보다는 위치 환경 차이로 보는 것이 맞습니다.

## 8. 향후 업데이트 방향

다음 업데이트는 맞춤 APK가 아니라 공통 배터리 보호 로직으로 가는 것이 맞습니다.

목표는 안정적인 사용자에게는 기존 반응성을 유지하고, GPS가 불안정한 사용자에게만 자동으로 감시 강도를 낮추는 것입니다.

### 1. 네이티브 active 위치요청 backoff

timeout 또는 낮은 정확도가 반복되면 네이티브 보조 감시가 바로 active 위치요청을 반복하지 않도록 합니다.

예상 정책:

```text
timeout 1회: 다음 active 요청 최소 2분 후
timeout 2회 이상: 다음 active 요청 최소 5분 후
그 사이에는 lastKnown 우선 사용
```

### 2. Flutter/네이티브 위치요청 공유 쿨다운

Flutter가 최근 60~90초 안에 위치 확인을 수행했다면 네이티브는 active 위치요청을 생략하고 lastKnown만 확인합니다.

반대로 네이티브가 방금 위치를 확인했다면 Flutter도 다음 확인에서 active 요청을 줄이는 방향을 검토합니다.

### 3. 명확한 범위 밖 상태의 감시 완화

반경 50m 기준으로 120m 이상 떨어진 상태처럼 명확히 범위 밖이면 30초 감시를 유지하지 않습니다.

예상 정책:

```text
범위 안 또는 진입 의심: 15~30초
경계 근처: 60초
명확한 범위 밖: 120초 이상
GPS 불안정 반복: 300초까지 완화
```

### 4. 경계 흔들림 누적 판단

`범위 안 보류`, `경계 흔들림`, `EXIT 후 GPS 흔들림 무시`가 연속 발생하면 위치 불안정 상태로 보고 감시 주기를 완화합니다.

- `Flutter감시` 횟수
- `위치요청` 횟수
- `lastKnown` 횟수
- `실패/timeout` 횟수
- `실행지연` 횟수
- 네이티브 배터리 요약의 `위치체크`, `위치요청`, `timeout`, `lastKnown`

## 9. 사용자에게 요청할 확인 항목

다음 사용자 테스트에서는 전체 런타임 로그 대신 아래 파일을 우선 요청합니다.

```text
nh_alimi_user_diagnostic.txt
```

가능하면 함께 받을 항목:

- 앱 배터리 사용량 스크린샷
- 위치 권한 화면 스크린샷
- 배터리 제한 설정 화면 스크린샷
- 테스트 시간대
- 실제 위치가 실내/지하/이동 중이었는지 여부

## 10. 다음 판단 기준

다음 로그에서 아래 패턴이면 배터리 보호 로직 추가가 필요합니다.

```text
15분 동안 위치요청 15회 이상
timeout 2회 이상
lastKnown 사용이 반복됨
예약간격이 계속 30초 이하
네이티브 위치요청이 1시간 60회 이상
```

반대로 아래 패턴이면 현재 `userdiag-ver2`만으로도 원인 추적은 충분합니다.

```text
15분 동안 위치요청 5~10회 이하
timeout 거의 없음
예약간격 60~120초로 안정화
배터리 감소가 완만함
```

## 11. 최종 정리

오늘 작업의 핵심은 다음입니다.

```text
user-ver1은 배터리 개선 반영 배포 기준 APK로 유지.
타사용자 배터리 문제는 특정 위치 환경에서 위치요청이 과하게 누적된 문제로 판단.
userdiag-ver2는 전체 로그 대신 핵심 진단 요약을 수집하기 위한 배포 후보.
다음 실제 개선은 GPS 불안정/timeout/경계 흔들림에 대한 공통 backoff 로직 추가.
```
