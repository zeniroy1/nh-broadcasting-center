## 1. 배경 — 이번 커밋(0529수정)이 한 일

초기 알림(지오펜스 진입 전 조기 경보)의 **정확성을 높이기 위해** 발동 조건을 보수화했다.

- 초기 알림 거리 상한: 70m → **60m** (`maximumInitialAlertThresholdMeters`)
  - `initialAlertThreshold = (radius+40).clamp(60,60)` → 사실상 **항상 60m 고정**
- 발동 조건 강화: 기존 `isInitialAlertCandidate` 단독 → `isInitialAlertCandidate && (isStrong || approachPendingActive)`
- 신규 "접근대기(approach pending)" 상태머신 도입 (native Kotlin + Flutter Dart 양쪽)
- 임계값 정리
  - strong 후보: 거리 ≤50m & 정확도 ≤80m
  - 접근대기 seed: 거리 60~80m & 정확도 ≤30m, 유효 5분, 120m 초과 시 해제

코드 검수 결과 컴파일/충돌/상태 꼬임 등 치명 버그는 없음. 머지 충돌 마커 없음, 변수 선언/시그니처 정상.

## 2. 발견한 핵심 사각지대

> **거리상으로는 지오펜스 안쪽 또는 근처인데, 정확도가 계속 80m를 초과해 나쁜 경우 → 알림이 보류될 수 있다.**

원인: 단일 위치 샘플 하나로 판단하기 때문.

- strong 후보: 정확도 ≤80m 요구 → 실패
- reliableInside: 정확도 ≤35m(기본) 요구 → 실패
- 접근대기 seed: 정확도 ≤30m로 시작 요구 → 미충족 시 미활성
- 결과: 실제로 안쪽인데 알림이 안 옴

### 현 설정 기준 위험도 평가

- 지오펜스 반경: 기본 30m / 범위 20~50m (작음)
- 반경이 strong 거리(≤50m) 안에 통째로 들어오므로, **체류 중 거리는 항상 ≤50m** → 정확도만 ≤80m면 strong 경로로 발동
- 네이티브 샘플 주기: 접근 시 60초 / 평상시 120초 → 5~10분 체류면 3~10회 샘플
- 따라서 "5~10분 체류 중 알림 누락" 위험 자체는 **작음**
- 남는 사각지대는 **"안쪽인데 정확도가 만성적으로 80~120m+로 나쁜 장소"**(실내·도심 협곡 등)에 한정

### 이것은 버그가 아니라 정책 선택

- 정확도 기준 낮게(엄격): 오탐↓ (예: 회사 안에서 서대문역 알림 같은 GPS 튐/캐시 오탐 감소), 실탐↓
- 정확도 기준 높게(완화): 실탐↑, 그러나 GPS 튐/캐시 오탐↑

단순히 정확도 상한을 120m로 올리는 건 오탐을 같이 키운다.

## 3. 합의된 방향성 — "접근추세(approach trend) 보정"

### 핵심 원칙

> **정확도 기준을 무작정 올리지 않는다. 거리 감소 흐름(접근 추세)이 확인될 때만 정확도 기준을 완화한다.**

단일 샷의 약점(거리값도 같은 부정확한 좌표에서 계산됨)을 **다중 샘플 추세**로 보완한다. 무작위 노이즈가 여러 샘플에 걸쳐 연속 단조 감소를 만들 확률은 낮으므로 통계적으로 방어된다.

예시 흐름:

```
73m / 정확도 20m
66m / 정확도 40m
57m / 정확도 100m
```

→ "GPS가 흐려졌지만 사용자가 기준점 쪽으로 들어오고 있다"고 추론 가능 → 정확도 100m라도 알림 허용.

### 새 발동 구조 (4단계)

```
알림 허용 (미차단 전제):
  - strong 후보   : 거리 ≤50m & 정확도 ≤80m
  - reliableInside: 반경 안 & 정확도 ≤35m
  - 접근대기      : 60~80m에서 정확도 좋은 접근 기록 있음
  - 접근추세(신규): 100m 이내에서 거리 감소 흐름 확인 + 현재 60m 안쪽/근처
```

### 접근추세 인정 조건 (초안)

1. 최근 5분 안의 위치값
2. 거리값이 100m 이내
3. 직전보다 거리가 감소
4. 총 감소폭이 최소 10~15m 이상
5. 현재 거리가 60m 이내 또는 근처
6. 정확도는 나빠도 최대 120~150m까지만 허용

### 배제 조건

1. 갑자기 150m 밖으로 튐
2. 거리 변화가 70m → 130m → 50m처럼 비정상적으로 출렁임
3. 5분 이상 지난 접근 기록
4. 이미 알림 차단 상태(`dismissedUntilExit = true`)
5. 알림 활성(`notifActive = true`)

### 기대 효과

- GPS 정확도 단일 값에만 의존하지 않음
- 실제 이동 방향(접근)을 반영
- 추가 고정밀 GPS 요청 불필요 → 배터리 영향 거의 없음 (기존 샘플 기록만 누적)
- "안쪽인데 정확도만 나빠서 알림이 안 오는 문제" 완화
- 오탐은 덜 늘리고 실탐은 올림

## 4. 구현 전 반드시 반영할 보강 4가지 (검수 의견)

### #1. 좋은 정확도 샘플로 추세를 '앵커'한다 (중요)

세 샘플이 전부 정확도 100m+면 십몇 m 감소는 노이즈일 수 있다. 추세 인정 시 **시작점(또는 최근 N개 중 하나)의 정확도가 양호**해야 한다는 닻을 건다.
→ 이는 기존 접근대기 seed(정확도 ≤30m 시작)와 동일 개념. **"접근추세 = 접근대기의 확장"**으로 설계하면 자연스럽다. seed로 신뢰할 출발점을 잡고, 이후 정확도가 흐려져도 거리가 줄면 발동 허용.

### #2. 1스텝이 아니라 최소 2스텝(샘플 3개) 연속 단조 감소를 요구

"직전보다 감소 + 총 감소폭 ≥10~15m"에 **"최근 ≥2회 연속 감소"**를 추가 → 우연한 1회 감소 오탐 제거.

### #3. 접근추세는 기존 게이트의 OR 가지로 넣으면 안 된다 (구조 함정)

현재 발동 조건이 전부 `isInitialAlertCandidate`(내부에 정확도 ≤120m 포함)와 AND로 묶여 있음. 접근추세를 그 안에 OR로 끼우면 정확도 120m에서 막혀 150m까지 살아나지 않음.
→ **접근추세는 `isInitialAlertCandidate`의 자식이 아니라 형제(병렬 경로)**로 두고, 자기 안에 거리·정확도(≤150) 검사를 독립으로 갖는다.

```
발동 = 미차단 && ( (초기후보 && (strong || 접근대기)) || 접근추세확정 )
```

### #4. "60m 이내 또는 근처"의 '근처'를 숫자로 못박는다

예: `현재 거리 ≤ 65m`. 모호한 표현은 native/dart 두 곳에서 다르게 구현될 위험.

### 추가 디테일

- 발동 후 추세 버퍼 초기화(기존 `clearApproachPendingState` 패턴) → 재발동 루프 방지
- 추세 판정에 **최근 2~3개 (시각:거리:정확도) 이력 저장** 필요 → 현재 single slot이라 ring buffer로 확장
- native(Kotlin) / Flutter(Dart) **양쪽 동일 구현·동기화** 필요 (구현 비용 2배)
- 기존 "write-only"로 지적된 키(`approach_pending_distance_m`, `approach_pending_accuracy_m`)가 이 이력 저장소의 출발점
