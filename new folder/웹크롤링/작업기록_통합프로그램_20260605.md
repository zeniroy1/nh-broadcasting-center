# LH/HUG 통합 프로그램 작업 기록

작성일: 2026-06-05
작업 폴더: `D:\codding\new folder\웹크롤링`

## 최종 방향

LH/HUG를 하나의 통합 UI에서 탭으로 구분해 실행하는 프로그램으로 정리했다.

- LH: 화면캡처/PNG/OCR 방식 제거, LH 공고 페이지 직접 크롤링 방식 적용
- HUG: 기존 직접 파싱 방식 유지
- 결과: LH/HUG 산출물을 공통 결과 탭에서 확인, 열기, 폴더 열기, 내보내기 가능
- 배포: Python 3.10 포함형 설치 EXE로 전환

## 주요 변경 사항

### 0. 공통 지표 풀 추가

LH/HUG/SH/GH 확장을 위해 공통 지표 풀을 추가했다.

파일:

`app/config/metrics_registry.json`

역할:

- 사이트별 원본 컬럼명을 표준 지표로 매핑
- 같은 의미의 다른 표현을 별칭으로 관리
- 경쟁률 분석에 필요한 필수 지표 세트 정의
- SH/GH 추가 시 코드 수정 범위를 줄이고 지표 별칭 추가 방식으로 확장

현재 등록된 표준 지표 예시:

- 공고명
- 공고지역
- 접수기간
- 접수시작일시
- 접수마감일시
- 청약상태
- 주택정보
- 주택형
- 전용면적
- 주소
- 공급호수
- 예비자 모집인원
- 신청건수
- 경쟁률
- 임대보증금
- 월임대료
- 기준지점거리
- 예상소요시간
- 종합점수

경쟁률 분석 가능 여부는 기본적으로 `공급호수` 계열 지표와 `신청건수` 계열 지표가 모두 있는지 확인한다. 따라서 접수예정/접수중 공고라도 신청건수 기반 경쟁률 표가 없으면 LH 분석 후보에서 제외된다.

### 1. LH 수집 방식 변경

기존 LH 방식은 PNG 캡처 파일을 넣고 OCR로 공고를 식별한 뒤 데이터를 산출하는 구조였다.

현재는 다음 방식으로 변경했다.

1. 사용자가 LH 탭에서 지역명 입력
2. 지역을 선택 목록에 추가
3. `공고 일정 확인` 실행
4. LH 공고 목록에서 선택 지역과 일치하는 공고를 탐색
5. 각 공고 상세 페이지에서 접수기간을 확인
6. 접수마감 공고와 분석 가능한 공급/신청 표가 없는 공고는 제외
7. 접수예정/접수중 공고만 후보 목록에 표시
8. 사용자가 후보 공고를 선택
9. `선택 공고 분석` 실행
10. LH 상세 페이지 직접 크롤링 후 기존 경쟁률/거리/요약 산출 로직으로 TXT/CSV 생성

따라서 더 이상 LH 화면캡처기, PNG 입력, EasyOCR, torch, opencv가 필요하지 않다. 또한 LH 분석 앞단은 특정 공고명에 고정하지 않고 접수일 기준으로 후보를 거른다.

### 2. LH 지역명 매칭

지역명은 완전 일치만 보지 않고 포함/별칭 기반으로 처리한다.

예시:

- `서울` 입력 시 `서울특별시`, `서울지역본부`, 공고명 내 `서울` 매칭 가능
- `인천` 입력 시 `인천광역시`, 공고명 내 `(인천)` 매칭 가능
- `부산`, `울산` 입력 시 `부산울산` 묶음 공고 매칭 가능

### 3. LH 청약 상태 지표 추가

LH 산출물에 다음 컬럼/지표를 추가했다.

- `청약상태`
- `접수기간`

반영 위치:

- LH TXT 보고서 상단 전체 요약
- LH TXT 보고서 내 각 표
- LH 전체 데이터 CSV
- LH 거리 데이터 CSV

예시:

- 청약상태: `청약신청전`
- 접수기간: `2026.06.08 10:00 ~ 2026.06.09 16:00`

신청건수가 0으로 나오는 경우, 현재 LH 원본이 `청약신청전`이면 정상적인 원본 상태로 판단한다. 계산식은 변경하지 않았다.

### 4. HUG 구조

HUG는 기존 직접 파싱 방식을 유지했다.

- 지역명 직접 추가 가능
- 추가한 지역 삭제 가능
- 처음에는 고정 지역이 표출되지 않음
- 선택한 지역만 파싱
- 결과는 `hug/outputs`에 저장
- 접수기간이 있는 행만 유효 공고로 판단
- 현재 사이트에 공고일정이 없으면 CSV/TXT 결과물을 생성하지 않음
- 공고일정이 없는 지역은 기존 해당 지역 HUG 결과 파일도 삭제해 오래된 결과가 남지 않게 처리

현재 HUG에는 LH처럼 명확한 `청약신청전/접수중/마감` 상태값과 접수기간을 동일한 형태로 제공받는 구조가 확인되지 않아, 청약상태 지표는 LH에만 적용했다.

### 5. UI 변경

LH 탭에서 제거된 항목:

- 화면캡처기 실행
- PNG 입력
- PNG 목록
- 목록 제외

LH 탭 현재 구조:

- 지역 선택 영역
- 지역명 입력
- 추가 버튼
- 삭제 버튼
- 공고 일정 확인 버튼
- 접수예정/접수중 후보 공고 목록
- 선택 공고 분석 버튼

HUG 탭도 같은 방식의 지역 추가/삭제 UI를 사용한다.

### 6. 진행 게이지

LH/HUG 실행 시 상단 진행 게이지가 표시된다.

- LH 공고 일정 확인 중
- LH 선택 공고 분석 중
- HUG 파싱 진행 중
- 단계별 안내 문구 표시
- 완료/실패 상태 표시

### 7. 결과 폴더

최종 산출물 위치:

- LH 결과: `lh/outputs`
- HUG 결과: `hug/outputs`

결과 탭에서는 `*.csv`, `*.txt` 산출물을 표시한다.

예전 PNG 기반 `capture_...` 산출물은 파일 자체를 삭제하지 않고, 결과 탭에서는 숨기도록 처리했다.

## 배포 구조

### 설치 EXE

최종 배포 파일:

`D:\codding\new folder\웹크롤링\_배포\LH_HUG_통합프로그램_설치.exe`

### 실행 방식

실행 흐름:

1. BAT 실행

4. 필수 패키지 설치

추후 선택 가능:

- CMD 없는 무창 실행 EXE

## 현재 주의사항

1. `127.0.0.1:8765`는 각 PC 자기 자신을 의미한다.
   - A PC에서 실행하면 A PC의 프로그램
   - B PC에서 실행하면 B PC의 프로그램

2. LH 신청건수는 원본 LH 페이지 기준이다.
   - 공고가 청약신청전이면 신청건수가 0일 수 있다.
   - 접수 시작 후 다시 파싱하면 갱신된 값으로 산출된다.

3. HUG에는 현재 LH와 같은 청약상태/접수기간 지표를 적용하지 않았다.
   - HUG 원본에서 동일한 상태 데이터가 안정적으로 확인되면 추후 추가 가능하다.

4. 현재 실행 방식은 BAT/CMD 기반이다.
   - 초기 배포/테스트에는 오류 확인이 쉬움
   - 추후 무창 실행 EXE로 개선 가능
