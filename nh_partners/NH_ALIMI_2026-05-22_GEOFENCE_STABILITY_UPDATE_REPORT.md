```text

```

분석한 원인은 두 갈래다.


특히 수동 모니터링, 위치보정, 기준점 변경이 차단 플래그를 어떻게 다루는지가 중요했다.

### 3.2 차단 플래그와 알림 재시작

`dismissedUntilExit:true`는 사용자가 이미 NH파트너스 앱을 확인해서 알림을 멈춘 상태를 의미한다.

이 상태에서는 같은 자리에서 모니터링을 껐다 켜거나 기준점을 다시 적용해도 알림이 즉시 재시작되면 안 된다.

수정 기준:

```text
모니터링 재개:
  감시는 재개
  dismissedUntilExit 유지

위치보정:
  위치만 보정
  dismissedUntilExit 유지

서대문역 기본 위치 복구:
  기준점만 복구
  dismissedUntilExit 유지

날짜 변경/06:00 자동 시작:
  새 하루 시작이므로 dismissedUntilExit 초기화 가능
```

### 3.3 알림 폭주

차단 플래그를 너무 쉽게 풀면 다음 문제가 생긴다.

### 12.10 다음 버전 검토 방향: 거리 추세 기반 알림 보정

2026-05-29 버전은 다음 정책으로 정리됐다.

```text
초기 알림 후보 절대 상한: 60m
strong 후보: 50m 이내 + 정확도 80m 이하
접근대기 seed: 60~80m + 정확도 30m 이하
접근대기 유효시간: 5분
추가 고정밀 GPS 요청 없음
```

이 구조는 오탐 방지에는 유리하지만, 다음 상황에서는 실탐이 지연되거나 보류될 수 있다.

```text
거리상으로는 지오펜스 안쪽 또는 근처
하지만 GPS 정확도가 계속 80m 초과
예: 57m / 정확도 100m
```

단일 샘플만 보면 이 값은 신뢰하기 어렵다. 정확도 100m라는 뜻은 좌표 자체가 약 100m 범위에서 흔들릴 수 있다는 의미이므로, 그 좌표에서 계산한 거리값도 함께 흔들린다. 따라서 "정확도는 무시하고 거리만 믿는 방식"은 위험하다.

다만 연속 샘플의 흐름을 보면 다른 판단이 가능하다.

```text
73m / 정확도 20m
66m / 정확도 40m
57m / 정확도 100m
```

이 경우 마지막 샘플의 정확도는 낮지만, 앞선 샘플들이 기준점 쪽으로 계속 접근하는 흐름을 보여준다. 즉, 단일 위치값이 아니라 "접근 추세"를 근거로 알림 신뢰도를 보강할 수 있다.

#### 핵심 설계 원칙

다음 버전에서 검토할 방향은 "정확도 기준을 무작정 완화"하는 것이 아니다.

```text
정확도 80m 기준을 단순히 100~120m로 올리면 오탐 위험이 커진다.
거리값 하나만 믿으면 GPS 튐에 취약하다.
따라서 최근 거리 흐름을 함께 보고, 접근 추세가 있을 때만 정확도 기준을 부분 완화한다.
```

즉, 다음 버전의 목표는 다음과 같다.

```text
오탐 방지 정책 유지
지오펜스 안쪽 체류 중 정확도만 나빠 알림이 보류되는 문제 완화
추가 고정밀 GPS 요청 없이 배터리 안정성 유지
기존 3.3 계열의 단순성 유지
```

#### 제안 로직 1: 3샘플 접근추세 보정

최근 위치 샘플 3개만 저장한다.

저장 후보:

```text
최근 5분 이내
거리 100m 이내
정확도 150m 이하
dismissedUntilExit=false
notifActive=false
```

접근추세 인정 조건:

```text
최근 3개 샘플의 거리가 대체로 감소
예: 82m -> 71m -> 58m
총 감소폭 15m 이상
현재 거리 60m 이내 또는 60m 근처
```

알림 허용:

```text
기존 strong 후보가 아니더라도
접근추세가 확인되고
현재 위치가 60m 이내이면
초기 알림 후보로 허용
```

이 방식의 의미:

```text
정확도가 낮은 단일 샘플은 그대로 믿지 않는다.
하지만 기준점 쪽으로 이동하는 흐름이 확인되면 실제 진입 가능성을 높게 본다.
```

#### 제안 로직 2: GPS 스파이크 배제

거리 추세를 보려면 GPS 튐을 반드시 배제해야 한다.

배제 예:

```text
120m -> 42m -> 135m -> 55m
```

이런 패턴은 실제 이동이라기보다 GPS 캐시/튀는 좌표일 가능성이 높다.

단순 배제 기준:

```text
직전 채택 샘플 대비 거리 변화가 비정상적으로 큼
예: 짧은 시간에 100m 이상 급변
또는 계산상 이동속도가 30m/s를 초과
```

처리:

```text
해당 샘플은 접근추세 계산에서 제외
알림 발동 근거로 사용하지 않음
필요 시 접근대기 상태도 해제
```

#### 제안 로직 3: 안쪽 체류 보강

사용자가 이미 지오펜스 안쪽에 멈춰 있으면 거리가 계속 감소하지 않을 수 있다. 이 경우 접근추세만 보면 알림이 늦어질 수 있으므로, 안쪽 체류 조건을 별도로 둔다.

체류 인정 조건:

```text
거리 60m 이내 샘플이 2회 연속
정확도 150m 이하
두 샘플 모두 최근 5분 이내
dismissedUntilExit=false
notifActive=false
```

알림 허용:

```text
정확도 80m 이하 strong 후보가 아니더라도
60m 이내가 2회 연속이면
실제 안쪽 체류로 보고 알림 허용
```

이 방식은 다음 상황을 커버한다.

```text
실제로 지오펜스 안에 들어와 있음
하지만 주변 건물/실내/지하 영향으로 정확도가 90~120m로 나쁨
한 번의 샘플만으로는 불확실하지만, 2회 연속 안쪽이면 체류 가능성이 높음
```

#### 접근대기와의 관계

현재 접근대기는 그대로 유지한다.

```text
접근대기:
  60~80m + 정확도 30m 이하의 좋은 접근 샘플을 5분간 기억

접근추세:
  여러 샘플의 거리 감소 흐름을 보고 실제 접근을 추론

안쪽 체류:
  60m 이내 샘플이 연속될 때 실제 체류를 추론
```

역할 구분:

```text
접근대기 = 좋은 인접 샘플 1개 기반 보조 근거
접근추세 = 여러 샘플의 이동 방향 기반 보조 근거
안쪽 체류 = 이미 안쪽에 들어온 상황의 보조 근거
```
