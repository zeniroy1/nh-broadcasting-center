# LH/HUG 통합 프로그램 기획서

## 목표

- LH는 기존 PNG 기반 분석 방식을 보존한다.
- HUG는 사이트 직접 파싱 방식으로 분리한다.
- 하나의 프로그램에서 탭으로 구분해 실행한다.
- 미구현 기관은 화면에 표시하지 않는다.
- 지역, 파일명, 요약 규칙은 설정에서 수정 가능하게 둔다.

## 표준 설치 구조

통합 프로그램은 필수 파일의 위치를 표준화한다. 기존 파일이 다른 위치에 있더라도 설치 또는 정리 단계에서 아래 위치로 맞춘다.

```text
웹크롤링/
  app/
  lh/
    tools/
      화면캡처기.exe
    scripts/
      generate_reports.py
    inputs/
    outputs/
  hug/
```

필수 파일 기준 위치:

```text
LH 화면캡처기: lh/tools/화면캡처기.exe
LH 분석 스크립트: lh/scripts/generate_reports.py
```

프로그램 시작 시 필수 파일 존재 여부를 검사한다. 없으면 실행하지 않고 어느 파일을 어느 위치에 둬야 하는지 안내한다.

## 현재 활성 기관

- LH
- HUG

## LH 처리 원칙

- `lh/tools/화면캡처기.exe`를 통합 프로그램에서 호출한다.
- `lh/scripts/generate_reports.py`를 LH 분석 진입점으로 사용한다.
- 기존 분석 로직은 우선 보존한다.
- 지역 감지 우선순위는 이미지 내부 텍스트, 파일명, 사용자 확인 순서다.
- 현재 검증된 이미지 처리 품질을 유지하고 사용자에게 배율 옵션을 노출하지 않는다.
- 지역명과 공고 정보는 하드코딩하지 않고 설정 또는 감지 결과를 따른다.

## HUG 처리 원칙

- HUG는 HTML 표를 직접 파싱한다.
- HUG 지역은 고정 실행하지 않는다.
- 파싱 전 사용자가 어느 지역을 수집할지 반드시 확인하거나 직접 기입한다.
- 서울, 경기도, 인천은 기본 후보로만 제공한다.
- 새 지역은 지역명과 HUG 지역 코드를 입력해 수집할 수 있게 한다.
- 산출 파일명은 `hug_{지역}_분석데이터.csv`, `hug_{지역}_요약.md` 규칙을 따른다.
- 요약에는 보증금, 거리, 신청자수, 종합점수 기준 TOP 항목을 포함한다.

## HUG 지역 선택 흐름

1. 프로그램이 기본 후보 지역을 보여준다.
2. 사용자가 수집할 지역을 선택한다.
3. 기본 후보에 없는 지역은 지역명과 코드를 직접 입력한다.
4. 선택된 지역만 파싱한다.
5. 산출물은 선택 지역명 기준으로 저장한다.

## 단계별 진행

1. 기본 구조와 설정 파일 구성
2. 표준 설치 구조 정리 및 필수 파일 검사
3. HUG 파싱 모듈화
4. LH 기존 로직 연결
5. 탭 UI 구성
6. 설정 기반 요약 규칙 정리
7. 원클릭 실행 정리

각 단계가 끝나면 정적검사, 기능 충돌 가능성, 불필요 주석, 코드라인 정리를 검수한 뒤 다음 단계로 넘어간다.
