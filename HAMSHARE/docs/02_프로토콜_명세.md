# HAMSHARE 프로토콜 명세 v1.0

## 전송 경로

`Galaxy S23+ → 5GHz 모바일 핫스팟 LAN → Windows 10 수신기`

- 기본 포트: `57321`
- 전송 계층: HTTPS/TLS 1.2 이상
- 서버 인증: Windows 수신기에 생성한 자체 서명 인증서의 SHA-256 지문 고정
- 장치 인증: 최초 6자리 PIN 등록 후 256비트 Bearer 토큰
- 토큰 보관: Android Keystore AES-GCM, Windows에는 SHA-256 해시만 보관

## API

| 메서드 | 경로 | 인증 | 설명 |
|---|---|---|---|
| GET | `/api/v1/health` | 없음 | PC 이름, 프로토콜 버전, 인증서 지문 확인 |
| POST | `/api/v1/pair` | PIN | S23+ 등록 및 접근 토큰 발급 |
| POST | `/api/v1/transfers` | Bearer | 다중 파일 전송 목록 생성 |
| PUT | `/api/v1/transfers/{id}/files/{index}` | Bearer | 파일 본문 스트리밍 업로드 |
| GET | `/api/v1/devices` | Bearer | 등록 장치 목록 확인 |

인증 API는 다음 헤더를 사용한다.

```http
Authorization: Bearer <token>
X-HAMSHARE-DEVICE-ID: <android-device-id>
```

## 파일 규칙

- 최대 1회 파일 개수: 1,000개
- 최대 1회 총용량: 20GB
- 파일명은 서버에서 다시 정규화한다.
- 기존 파일은 덮어쓰지 않고 `(1)`, `(2)`를 붙인다.
- 수신 중에는 `.partial` 파일을 사용한다.
- 수신 크기와 SHA-256이 모두 일치한 경우에만 최종 파일명으로 변경한다.

## 최초 등록

1. PC가 PIN과 인증서 코드 앞 12자리를 표시한다.
2. 사용자가 Android 앱에 PC IP, 포트, 인증서 코드, PIN을 입력한다.
3. Android 앱은 TLS 인증서 SHA-256 지문의 접두사가 인증서 코드와 일치하는지 확인한다.
4. PIN이 맞으면 서버가 접근 토큰을 한 번 반환한다.
5. Android는 토큰을 Keystore로 암호화해 저장하고 Windows는 토큰 해시만 저장한다.

## 오류 코드

| 코드 | 의미 |
|---|---|
| `INVALID_DEVICE` | 장치 정보 누락 또는 오류 |
| `INVALID_PIN` | PIN 불일치 또는 만료 |
| `UNAUTHORIZED` | 토큰 또는 장치 ID 불일치 |
| `DEVICE_MISMATCH` | 다른 장치의 전송 접근 시도 |
| `INVALID_MANIFEST` | 파일 개수·용량·해시 형식 오류 |
| `INVALID_FILE` | 크기 또는 SHA-256 검증 실패 |
| `NOT_FOUND` | 전송 ID 또는 파일 인덱스 없음 |
