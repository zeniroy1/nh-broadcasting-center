# HAMSHARE 전체 구현계획서 및 기술 사용서

## 1. 문서 정보

- 프로젝트명: HAMSHARE
- 목적: Galaxy S23+에서 Windows 10 PC로 파일을 무선 전송하는 전용 시스템 구축
- 기준 전송 방식: Galaxy S23+의 5GHz 모바일 핫스팟을 이용한 로컬 Wi-Fi 전송
- 보조 연결 방식: Bluetooth는 향후 PC 식별·최초 인증 보조 기능으로 선택 적용
- 작성일: 2026-06-18
- 대상 운영체제: Android(Galaxy S23+), Windows 10 64비트
- 계획 단계: 설계 문서 작성만 수행하며 코드, 프로젝트 스캐폴딩, 패키지 설치 및 빌드는 수행하지 않음

## 2. 작업 통제 원칙

1. 사용자가 명시적으로 **“코딩을 시작해”**, **“N단계를 구현해”** 등 구현 승인을 내리기 전에는 어떠한 소스 코드도 작성하지 않는다.
2. 각 단계는 `설계 확정 → 구현 승인 → 구현 → 검증 결과 보고 → 사용자 인수 승인` 순서로 진행한다.
3. 다음 단계는 이전 단계의 사용자 인수 승인이 완료된 뒤에만 시작한다.
4. 승인 전에는 프로젝트 생성, SDK·라이브러리 설치, 방화벽 규칙 변경, 자동 시작 등록 등 시스템 변경도 수행하지 않는다.
5. 설계 변경이 발생하면 영향 범위, 보안 영향, 일정 영향을 먼저 문서화하고 사용자 승인을 받는다.
6. 삭제·덮어쓰기·외부 전송·방화벽 변경처럼 데이터나 시스템 상태에 영향을 주는 작업은 별도 명시적 승인을 받는다.

## 3. 목표와 범위

### 3.1 핵심 목표

- S23+에서 한 개 또는 여러 개의 파일을 선택하여 지정된 Windows 10 PC로 전송한다.
- 전송 데이터는 인터넷이나 외부 서버를 거치지 않고 모바일 핫스팟 내부 로컬 네트워크에서만 이동한다.
- Windows 수신 프로그램은 사용자가 지정한 폴더에 파일을 안전하게 저장한다.
- 전송 진행률, 성공·실패 상태, 무결성 검사 결과를 양쪽에서 확인할 수 있게 한다.
- 끊어진 전송의 재시도 또는 이어받기를 지원할 수 있는 구조로 설계한다.

### 3.2 1차 버전 포함 범위

- Android 파일 선택 및 공유 메뉴 연동
- Windows 수신 서버와 수신 화면
- 같은 모바일 핫스팟 네트워크에서 PC 자동 검색
- 최초 PIN 기반 페어링 및 승인된 PC 기억
- 암호화된 파일 전송
- 파일명 충돌 처리, 무결성 검사, 전송 기록
- 전송 취소, 오류 안내, 기본 재시도

### 3.3 1차 버전 제외 범위

- 삼성 Quick Share 프로토콜과의 호환
- 인터넷을 통한 원격 전송 및 클라우드 중계
- iPhone, macOS, Linux 지원
- 불특정 다수 PC에 대한 공개 수신
- 모바일 핫스팟의 완전 무인 자동 활성화
- Bluetooth 단독 대용량 파일 전송

## 4. 권장 시스템 구조

```text
[Galaxy S23+]
  Android HAMSHARE 앱
  - 파일 선택/공유 수신
  - PC 검색 및 인증
  - 파일 분할·암호화·전송
        │
        │ 5GHz 모바일 핫스팟의 로컬 Wi-Fi
        │ HTTPS 또는 TLS 적용 TCP
        ▼
[Windows 10 PC]
  HAMSHARE 수신 프로그램
  - 검색 응답 및 인증
  - 수신 승인/거절
  - 임시 파일 저장·검증·최종 이동
  - 기록/알림/설정
        │
        ▼
  사용자가 지정한 수신 폴더
```

### 4.1 기본 연결 시나리오

1. 사용자가 S23+에서 5GHz 모바일 핫스팟을 켠다.
2. Windows 10 PC가 저장된 핫스팟 프로필에 접속한다.
3. PC 수신 프로그램이 로컬 네트워크에서 수신 대기한다.
4. Android 앱이 PC를 검색하고 등록된 장치인지 확인한다.
5. Android 앱이 파일 메타데이터를 보내고 PC가 수신을 승인한다.
6. 파일 본문을 분할 전송한다.
7. PC가 전체 파일의 SHA-256을 검증한 뒤 임시 파일을 최종 파일명으로 변경한다.

## 5. 기술 사용 원칙

### 5.1 Android

- 언어: Kotlin
- UI: Jetpack Compose 우선 검토
- 최소 SDK: 실제 S23+ Android 버전과 배포 범위를 확인한 뒤 확정
- 파일 접근: Storage Access Framework와 `content://` URI
- 공유 연동: Android Sharesheet의 `ACTION_SEND`, `ACTION_SEND_MULTIPLE`
- 장시간 전송: 사용자에게 표시되는 Foreground Service
- 네트워크: Kotlin Coroutines 기반 비동기 처리
- 비밀정보 보관: Android Keystore
- 장치 검색: mDNS/NSD 또는 제한된 UDP 브로드캐스트 중 실기기 시험 후 선택

### 5.2 Windows 10

- 언어 및 런타임: C#과 Windows 10 호환 .NET 버전
- UI: WPF를 기본 후보로 하며 WinUI 사용 필요성은 별도 검토
- 수신 서버: ASP.NET Core/Kestrel 기반 HTTPS 또는 TLS 소켓 방식 비교 후 확정
- 설정 저장: 사용자 프로필 아래 애플리케이션 데이터 폴더
- 비밀정보 보관: Windows DPAPI 또는 인증서 저장소
- 알림: Windows 알림 기능, 실패 시 앱 내부 알림으로 대체
- 자동 시작: 기본 비활성화, 사용자 명시 승인 시에만 등록

### 5.3 통신 프로토콜

- 제어 메시지와 파일 데이터를 구분한다.
- 모든 요청에는 프로토콜 버전, 장치 ID, 전송 ID를 포함한다.
- 파일 메타데이터에는 원본 파일명, 크기, MIME 형식, 수정 시각, SHA-256을 포함한다.
- 파일은 고정 또는 가변 크기 청크로 전송하고 확인된 마지막 위치를 기록한다.
- 파일명은 경로 구분자와 예약 문자를 제거하여 경로 탈출 공격을 방지한다.
- 전송 중에는 `.partial` 임시 확장자를 사용하고 검증 성공 후 최종 이름으로 변경한다.
- 오류 코드는 네트워크, 인증, 저장 공간, 권한, 무결성, 사용자 취소로 구분한다.

### 5.4 보안

- 최초 페어링 시 PC 화면의 일회용 PIN을 휴대폰에 입력한다.
- 페어링 결과로 생성된 장기 장치 키는 각 운영체제의 보안 저장소에 보관한다.
- 승인되지 않은 장치의 검색 요청에는 최소 정보만 응답한다.
- 파일명, 파일 크기, 파일 내용은 인증된 암호화 채널에서만 전송한다.
- PC 수신 서버는 핫스팟의 사설 네트워크 인터페이스만 수신하도록 제한하는 방안을 검토한다.
- 외부 인터넷 중계 서버, 분석 SDK, 광고 SDK는 사용하지 않는다.
- 로그에는 파일 내용, PIN, 키, 토큰을 기록하지 않는다.

- 로컬 TCP 처리량 측정 도구(구현 승인 후 설치 여부 별도 승인)
- Windows 데이터 통신 연결 설정

### 시험 항목

- 5GHz 핫스팟 연결 여부
- 절전·화면 꺼짐·10분 이상 전송 시 연결 유지
- PC 유선 LAN과 휴대폰 핫스팟 동시 연결 시 라우팅
- 100MB, 1GB, 5GB 기준 처리량과 오류율
- USB 포트 위치, 발열 및 거리 변화에 따른 성능

### 산출물

- 네트워크 시험 결과표
- 목표 속도와 최소 허용 속도
- 권장 PC 네트워크 설정

### 검증

- 최소 3회 반복 측정 후 평균·최저 속도를 기록한다.
- 전송 데이터가 외부 인터넷을 통하지 않는지 확인한다.
- 모바일 데이터 사용량 증가 여부를 전후 비교한다.

### 사용자 인허가

- 사용자가 실제 속도와 운용 방식이 충분하다고 승인해야 3단계로 이동한다.
- 측정 도구 설치나 네트워크 설정 변경은 실행 전 별도 승인받는다.

### 목표

Android와 Windows 사이의 역할, 메시지, 상태 전이를 구현 가능한 수준으로 정의한다.

- UUID 기반 전송 ID와 장치 ID

### 설계 내용

- 프로토콜 버전 협상
- 타임아웃, 재시도 및 중복 요청 처리
- 이어받기 체크포인트 형식
- 최대 메시지·청크 크기

### 산출물

- 시스템 구성도
- API/메시지 명세
- 상태 전이도
- 오류 코드표

### 검증

- 정상 전송과 주요 실패 시나리오를 문서 시뮬레이션한다.
- 동일 요청 재전송 시 파일이 중복 생성되지 않는지 설계 검토한다.
- 향후 프로토콜 변경 시 이전 버전을 거부하거나 호환할 규칙을 확인한다.

### 사용자 인허가

- 사용자가 연결 흐름과 화면상 동작을 승인해야 4단계로 이동한다.
- 프로토콜 확정 후 변경은 영향 분석과 재승인을 거친다.

## 4단계 — 보안 및 페어링 설계

### 목표

지정 PC만 파일을 받고, 제3자가 파일명이나 내용을 열람·주입하지 못하도록 한다.

### 사용할 기술·도구

- TLS 1.2 이상
- 일회용 PIN 기반 최초 페어링
- Android Keystore
- Windows DPAPI 또는 인증서 저장소
- HMAC 또는 상호 인증 토큰
- 암호학적으로 안전한 난수 생성기

### 설계 내용

- 최초 등록, 재등록, 등록 해제
- 휴대폰 또는 PC 교체 시 복구 절차
- PIN 만료 시간과 실패 횟수 제한
- 신뢰 장치 목록과 장치 이름 표시
- 로그에서 개인정보와 비밀정보 제거

### 산출물

- 위협 모델
- 키·토큰 생명주기
- 페어링 및 등록 해제 절차
- 보안 실패 대응표

### 검증

- 미등록 장치, 잘못된 PIN, 재사용 PIN, 만료 토큰을 거부하는지 설계 검토한다.
- 경로 탈출 파일명과 비정상적으로 큰 메타데이터를 거부하도록 확인한다.
- 평문 파일 데이터나 비밀정보가 로그에 남지 않도록 확인한다.

### 사용자 인허가

- 사용자가 보안 수준과 최초 페어링 절차를 승인해야 5단계로 이동한다.
- 인증서 설치, 방화벽 규칙 추가는 실제 실행 전에 별도 승인받는다.

## 5단계 — Windows 10 수신 프로그램 설계 및 구현

### 목표

Windows에서 파일 수신, 임시 저장, 검증, 최종 저장을 담당하는 프로그램을 만든다.

### 사용할 기술·도구

- C#/.NET
- WPF
- Kestrel HTTPS 또는 확정된 TLS 소켓
- 비동기 스트림 I/O
- SHA-256
- Windows DPAPI

### 구현 예정 기능

- 수신 대기 시작·중지
- 장치 검색 응답 및 페어링
- 수신 승인·거절
- 저장 폴더 설정 및 여유 공간 확인
- `.partial` 임시 파일과 원자적 최종 이름 변경
- 진행률, 속도, 남은 시간, 기록 표시
- 파일명 충돌 처리

### 산출물

- Windows 실행 프로그램과 소스 코드
- 설정·로그 저장 규격
- Windows 설치 및 제거 절차 초안

### 검증

- 휴대폰 화면 꺼짐과 Windows 절전 정책

## 9단계 — 보안·복구·사용자 인수 시험

### 목표

실사용 배포 전에 보안과 장애 복구를 포함한 최종 품질을 확인한다.

### 사용할 기술·도구

- 사용자 인수 테스트(UAT) 시나리오
- 위협 모델 재검토
- 비정상 입력 및 경계값 시험
- 로그 진단과 개인정보 점검

### 시험 항목

- 미등록 장치와 잘못된 인증 시도 차단
- 악성 파일명, 중복 파일명, 매우 긴 파일명 처리
- 디스크 부족, 권한 거부, 네트워크 변경, 강제 종료 복구
- 등록 장치 삭제 후 재접속 차단
- 로그에 PIN, 키, 파일 내용이 없는지 확인

### 산출물

- UAT 결과서
- 알려진 제한사항
- 결함 목록과 해결 여부
- 복구 및 문제 해결 안내서

### 검증

- 모든 필수 UAT 항목을 사용자와 함께 확인한다.
- 치명적·높음 등급 결함이 남아 있지 않아야 한다.
- 남은 제한사항은 사용자가 명시적으로 수용해야 한다.

### 사용자 인허가

- 사용자가 UAT 결과와 알려진 제한사항을 승인해야 10단계 배포 준비로 이동한다.
- 보안상 중요한 미해결 결함이 있으면 승인 여부와 관계없이 배포하지 않는다.

### 목표

### 사용할 기술·도구

- Windows 설치 패키지 방식은 MSIX 또는 별도 설치 프로그램 중 확정
- Android 서명 APK
- 버전 관리 및 릴리스 노트
- 설정 백업·초기화 절차

### 배포 내용

- Windows 수신 프로그램 설치·제거
- Android 앱 설치와 업데이트
- 최초 페어링 안내
- 수신 폴더 변경, 등록 장치 삭제, 로그 확인
- 문제 발생 시 진단 정보 수집과 복구

### 산출물

- 최종 설치 파일
- 사용자 설명서
- 관리자·문제 해결 안내서
- 릴리스 노트와 파일 해시
- 소스 및 설계 문서 보관본

### 검증

- 깨끗한 Windows 10 환경에서 설치·실행·제거를 확인한다.
- S23+에서 신규 설치, 페어링, 전송, 재설치를 확인한다.
- 제거 후 사용자 파일이 임의 삭제되지 않는지 확인한다.
- 최종 배포 파일의 해시와 버전을 기록한다.

### 사용자 인허가

- 설치 실행, 방화벽 허용, 자동 시작, 실제 운영 전환은 각각 사용자의 최종 승인을 받는다.
- 사용자가 최종 인수 승인한 시점을 프로젝트 1차 버전 완료로 기록한다.

| 5 | Windows 프로그램 | 명시적 코딩 승인 전 소스 작성 |
| 6 | Android 앱 | 명시적 코딩 승인 전 소스 작성·APK 설치 |
| 7 | 통합·이어받기 | 실제 사용자 파일을 이용한 파괴적 시험 |

## 8. 성공 기준

- 지정된 S23+와 Windows 10 PC가 모바일 핫스팟에서 서로를 안정적으로 찾는다.
- 승인되지 않은 장치는 파일을 전송하거나 받을 수 없다.
- 1GB 이상 파일이 메모리 전체 적재 없이 스트리밍된다.
- 정상 완료 파일의 송신·수신 SHA-256이 일치한다.
- 전송 중단 시 불완전 파일이 완성 파일로 노출되지 않는다.
- 지원하기로 한 중단 상황에서 이어받기 또는 명확한 재시도가 가능하다.
- 실제 환경에서 합의한 최소 전송 속도와 안정성 기준을 충족한다.
- 모바일 데이터 외부 전송 없이 로컬 네트워크에서 파일이 이동한다.
- 사용자가 설치, 페어링, 전송, 오류 복구를 문서만 보고 수행할 수 있다.

## 10. 구현 착수 승인 문구

다음과 같은 사용자 지시가 있기 전까지 프로젝트는 설계 단계로 유지한다.

> HAMSHARE 코딩을 시작해. 우선 N단계를 구현해.

승인에는 착수할 단계와 범위가 포함되어야 한다. 승인받지 않은 후속 단계, 시스템 설정 변경, 패키지 설치 및 배포는 수행하지 않는다.
